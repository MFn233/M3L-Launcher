## P0 启动可靠性

- [ ] **收窄高风险兼容规则**（防过拟合，最重要）
  - `有 LWJGL3 就剔 LWJGL2` 收窄到 Cleanroom 特征
    （`mainClass = top.outlands.foundation.boot.Foundation` 或存在 `com.cleanroommc:*`）
  - `OptiFine 排到末尾` 收窄到 `optifine:OptiFine:…:installer` 且主类是 LaunchWrapper
  - 加一个「不做兼容处理」总开关，出问题能一键回到"照 JSON 原样"
- [ ] **离线回归** `tools/check-classpath.py`
  - 拿真实版本 JSON 做快照断言（classpath 条目、参数、缺库清单）
  - 每次改解析先跑一遍，保证"本来正常的实例不会被搞坏"
- [ ] **游戏 stdout 进 `m3l-launch.txt`**
  - 现状：`flush_lines` 直接写会话，游戏输出不进落盘文件（这次 FML 报错只能手工复现）
- [ ] **Java 决策表**（照成熟实现的做法）
  - 版本下限表：1.13→8、1.17→16、1.18→17、1.20.5→21、26.1→25
  - 约束：≤1.12 的 LaunchWrapper 强制 Java 8；`--sun-misc-unsafe-memory-access` 只对 24/25
  - `javaVersion.component` 与 `majorVersion` 的映射（`jre-legacy`=8、`java-runtime-delta`=21 …）
- [ ] **默认 JVM 参数按 key 级抑制**
  - `-Xmx` / `-Dkey=` / `-XX:Key` 首个已存在者胜，其余不追加（现在是整串比较）
- [ ] **natives 按平台目录**：`natives-<os-arch>`，每次启动清空后重解压（现在单目录 + 只补缺）
