# MFn's Minimalism Mclauncher 设计文档 v2

> 本文件是**设计源头**，只写结论，不写实现细节与踩坑（那些记在 `工作日志/`）。
> v1（`设计文档.md`）保留为历史版本，不再更新。

别称：**M³ Launcher** / **M3L** / **MMML**

---

## 一、定位

- 极简的 Minecraft 启动器，**仅支持 Windows**。
- 无视觉负担、无运行负担：无广告、无推送、无后台常驻。
- 绿色 portable：配置写在 exe 同目录的 `config.json`，不碰注册表，卸载即删目录。
- 精简不等于简陋：不以牺牲可定制性与美观为代价。

## 二、三件套

| 部分 | 职责 | 边界 |
|---|---|---|
| **MMM-C**（core） | 接收参数 → 找 Java → 拼命令 → 启动游戏 → 返回 PID 或错误码 | 不下载、不存配置、不做界面 |
| **MMM-L**（launcher） | 图形界面，让用户舒服地调用 core | 不内嵌游戏逻辑 |
| **MMM-DL**（downloader） | 下载并校验游戏本体、模组、整合包 | 只下载，不启动 |

- 三者**可分别替换**：core 可被别人的 GUI 调用，launcher 也可调用别人的 core。
- 三个名字都是独立工具，不是同一个程序的三块面板。

## 三、MMM-C（core）

- 存在形式：aardio 用户库（当前）、命令行 exe、DLL（后续可选）。
- 接口契约固定，任何语言都能调：

```
--game-dir --version --username --memory --java --work-dir
--uuid --access-token --user-type --version-type
--width --height --log-file --no-wait --dry-run --help
```

- 退出码：`0` 成功 / `1` 参数 / `2` Java / `3` 版本·库·natives / `4` 启动失败或游戏异常退出。
- 命令行形式的配置文件 `config.txt`（键值对，与 exe 同目录）：
  `username / memory / game_dir / version / java / width / height`。
- 代码要求整洁易懂，允许别人在此基础上写 TUI / CUI。

## 四、MMM-L（launcher）

### 1. 视觉

- 只用黑白灰，错误用红色。
- 微软雅黑（界面）+ Consolas（日志）。
- 内边距 24px 起，左对齐，靠排版而不是颜色制造层次。
- 图标：大写字母 M，右上角角标 3。

### 2. 主页

- 标题 `M³ Launcher`（左键打开「关于」，右键在调试模式下打开测试台）。
- 版本下拉框，悬停显示完整版本名。
- 启动游戏 / 设置两个按钮。
- 一行状态栏：登录方式、用户名、版本、内存；可在设置中关闭。
- 窗口可自由缩放。

### 3. 启动流程

- 按设置决定是否弹出日志窗口（默认弹）。
- 按设置决定启动后是否隐藏启动器。
- 游戏窗口大小三选一：手动（带「默认大小」按钮）/ 全屏 / 与启动器一致。
- Java 版本不匹配时提示「Java 版本有误」，提供：换用推荐版本 / 手动选择 / 强制使用当前版本。
  所有推荐版本都被拉黑时给出明确提示，并说明实际用了哪个 Java。
- 启动后状态栏提示「右键启动游戏可强制结束」，该功能必须可用。
- 允许多开（可设置）。多开时每个实例独占一份日志与崩溃窗口。

### 4. 设置

- **游戏设置**：用户配置（显示当前用户名与登录方式）、分配内存（滑条 + 输入 + 自动配置）、
  游戏窗口大小、Java 选择（输入 + Java 管理入口）、游戏路径（下拉 + 路径管理入口）。
- **启动器设置**：启动时弹日志、启动后隐藏、状态栏、调试模式、允许多开、进程优先级、
  崩溃时提示「请勿直接截图」。
- **Java 管理**：自动检测、列出版本与厂商、手动添加、拉黑、重新检测、打开目录。
  `[黑名单]` / `[当前]` 前缀标在名字前。
- **游戏路径管理**：自动检测官方目录；允许多条 `.minecraft` 路径，可增删改名；
  官方目录不可删除。`[官方]` / `[当前]` 前缀标在名字前。
- **版本管理**：四列——版本名 / 游戏版本 / 加载器 / 隔离；可切换隔离、重命名、删除（进回收站）、打开目录。
- **用户配置**：多账号管理；离线账号支持自定义 UUID。正版与外置登录后续再做。

### 5. 崩溃处理

- 游戏异常退出（退出码非 0 且不是用户手动结束）时弹崩溃窗口。
- 内容顺序：**原因**（最多 3 条）→ 疑似相关模组 → 提示 → 关键信息 → 日志列表 → 操作按钮。
- 原因来自规则表，覆盖 Java 版本、内存、显卡、模组冲突、依赖缺失、安装不完整等常见情形。
- 疑似模组从崩溃报告栈帧里提取，命中 `mods/` 里的 jar 时直接显示 jar 名。
- 崩溃窗口**禁止被截图**（`SetWindowDisplayAffinity`），引导用户走「打包日志」。
- 支持多实例同时崩溃：窗口非模态、按阶梯错开。
- 操作：打开日志 / 打开所在目录 / 打包日志 / 复制诊断信息。

- 祈使句 + 「请」，不出现「你 / 我们 / 别担心」。
- 现象 + 处理两段式；具体值用冒号；技术细节放全角括号。
- 界面元素用「」；强警告才用 `！！！`。

## 五、MMM-DL（downloader）

- 只下载，不做别的；界面风格与启动器一致。
- 下载并校验版本完整性。
- 对接 Modrinth / CurseForge / MC 百科等平台，支持整合包、模组、资源包、光影；
  能跳转 MC 百科条目查看说明。
- 支持自动/手动安装模组加载器（Forge / NeoForge / Fabric / Quilt，以及冷门加载器）。
- 支持镜像源切换；支持 P2P 加速。
- 下载完成后在版本目录写入边车文件 `.m3l.json`：

```json
{
    "game": "1.20.1",
    "loader": "Fabric",
    "loader_version": "0.19.3",
    "source": "mmmd"
}
```

  启动器只在**存在**该文件时采信它；没有就按版本 JSON 推断。边车不参与启动，删掉也能玩。

## 六、数据与目录约定

- 配置：`config.json`，与 exe 同目录，纯文本。
- 版本隔离：开启时游戏目录为 `versions/<版本名>`，关闭时与其它版本共用 `.minecraft` 根。
- 删除版本/路径：进回收站，可恢复；不提供「永久删除」以外的静默破坏。
- 重命名版本：目录、json、jar 一起改名，JSON 的 `id` 同步更新（`--version` 依赖它）。
  由此带来的已知行为：外部改名后「游戏版本」可能显示成新名字，除非有边车文件。

## 七、技术选型

- 语言/工具：**aardio**（Windows 原生、体积小、单文件发布）。
- 界面：aardio 的 `win.form` + `plus` 控件；主题集中在 `launcher/MMMLauncher/lib/m3theme.aardio`。
- 核心库：`core/launch/MMMLC.aardio` 为权威源码，部署到 aardio 用户库目录后由两个工程 `import`。
  下载核心将来放 `core/download/MMMDLC.aardio`，命名规则与启动核心成对。
- 发布：aardio 工程发布为单个 exe（约 2.4 MB），lib 内嵌。

## 七之二、仓库分层

目录按**功能**分层，不按角色命名，避免"两个 core"的歧义：

```
core/          无界面、可被 embed 的核心
  launch/      MMM-C：启动核心（MMMLC）
  download/    下载核心（MMMDLC）
launcher/      MMM-L：启动器界面
downloader/    MMM-DL：下载器界面
```

- 每个核心都能被第三方项目 `import`，不绑定自家 GUI。
- 不提前抽象"各核心共用的底层库"：等真的出现第二次重复实现再抽。
