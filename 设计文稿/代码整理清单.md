## P0 结构：settings2 拆开

`settings2.aardio` 2 835 行，里面积了三件互不相干的东西：

| 段落 | 行数 |
|---|---|
| 版本独立设置（含 Mod 元数据分批扫描） | ~1 000 |
| 账户管理 / Java 管理 / 路径 / 版本 | ~1 300 |
| 分页骨架、草稿、事件、内存估算 | ~500 |

拆法（不改变行为，纯搬移）：

1. Mod 元数据扫描（571 行那一节）→ `lib/m3modui.aardio`，只留"渲染 + 触发"
2. 版本独立设置页 → `dlg/settings_pv.aardio`（和账户页一样做成独立子对话框）
3. 账户页 → `dlg/settings_acc.aardio`

风险点：这些段共享 `cfg`、`winform`、`P3A/PV` 等局部量，搬的时候要么传参，要么放进同一个作用域对象。

## P0 一致性：`m3config.update(fn)`

29 处 `save_keys` 全是这个模式：

```aardio
var cfg = m3config.read();       // 打开界面时的快照
... 用户改了点什么 ...
cfg.x = 1;
m3config.save_keys(cfg, {"x"});  // 只回写 x
```

今天已经因此踩了两次（`action_log` 开关被翻两次、`account_key` 没固化）。
加一个原子修改助手：

```aardio
m3config.update(function(cfg) {
	cfg.action_log = !cfg.action_log;
});
```

内部：read → 改 → save，一步到位；调用方拿不到过期快照。然后逐个替换高频路径（菜单、账户页、登录落库）。

## P1 界面：`m3theme.window(winform)`

12 个对话框的 DSG 里都写着 `bgcolor=0xF2F2F2`，字号也各写一遍。
