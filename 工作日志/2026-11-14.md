## 改名与 Minimalism 约束评估（16:45）

**问题**：要不要解除 Minimalism 这个束缚、给项目换个名字。

**先量化成本**

| 记号 | 出现处 | 性质 |

| `M3L` | 266 | 配置目录 `M3L\`、`m3l-*` 文件前缀、GitHub 仓库名、Azure 应用显示名 |
| `MMML` | 219 | 工程名 `MMMLauncher`、核心 `MMMLC`、命名空间前缀 |

| `Mclauncher` | 7 | README 标题、设计文档 |

**结论（建议）：改名不划算，改"承诺"才划算。**

- 用户可见名 × 内部标识已经绑死：只改外面的名字，代码里还是 `m3*`/`MMML`，
  等于自己造一个"界面叫 X、代码叫 Y"的长期歧义；
- 外部锚点已经落地：GitHub 仓库、Azure 应用显示名（登录时会显示给用户）、
  `M3L\` 数据目录、`m3l-*` 文件前缀。每一个改名都要迁移或留兼容；
- `M³` 这个写法本身有硬伤：打不出来、搜不到，真要做分发反而是劣势。

**Minimalism 现在实际在约束什么**

它约束的不是"功能少"，而是"不打扰"。项目一直成立的那几条：
无广告、无推送、无后台常驻、黑白灰、绿色免安装、单文件配置。
真正变的是它已经会做登录/Mod/崩溃分析——那叫"专一"（只做启动这一件事），
不叫"功能少"。所以把口号从「极简」改成「专一且不打扰」，比换名字更有效，
也顺手把下载器（MMM-DL）独立出去，启动器就不必被迫"什么都做"。

## 发布版启动游戏报错、F5 不报（17:00）

**用户现象**：IDE 里 F5 能启动游戏，发布的 exe 不行，且**只有发布版报错**。

**已查到的证据**

  版本号三处一致（`0.2.2.5` / `0.2.2` / `0.2.2.5`）；
- 发布版本身**能启动**（我这边跑起来窗口正常，进程存活）；
- 但 `versions/1.11.2/m3l-launch.txt`（16:48 那次，发布版写入）显示：
  Java 8 + Forge 13.20.1 已经开始加载 tweak，**16:48:34 之后就没了**，
  既没有 `游戏已退出，退出码`，也没有 crash-report / hs_err；

- 启动时记一行：`启动器启动：exe=…，数据目录=…` —— 直接确认发布版读的是哪份配置。

## 发布版不能启动游戏的结论：未签名 exe 被拦（18:05）

**现象链**

- F5（aardio.exe，签过名、有信誉）→ 一切正常；
- 发布版（我们自己的 exe，未签名、无信誉）→ 启动游戏失败；
- 提权运行 → 正常；
- 自检日志给出错误码：`游戏目录：不可写（拒绝访问。Error Code: 0x5(5)）`；
- 目录 DACL 查过：`Authenticated Users = Modify`，属主是当前用户 → 权限本身没问题；
- 用户手动在资源管理器新建文件 → 成功；把 exe 加进信任项 → 仍然不能写。

**结论**：不是 ACL、不是路径、不是代码，是 Windows 按「签名 / 信誉」限制未知 exe。
加 Defender 排除项没用，因为排除项按**路径**生效，而拦截按**签名与信誉**判定；
而且每次重新发布 hash 都变，信誉从零开始 —— 这是「上一版能跑、这一版又不行」的根源。

**本轮代码侧收尾**

- `main`：启动前写权限自检（分步：建目录 / 写文件，带 Windows 错误原文）；
- 不可写时提示直接指向「安全软件拦截」这一可能，并给两条对策；
- 提示框 460×180 → 520×300，长消息不再被裁。

**用户决定**

不做「启动器不写游戏目录」的改造；下一步自己试代码签名或提交误报。
