# 工作日志 2026-11-11

## 复核 slogan「专一且简单」（20:55）

**当前事实**（`tools/` 外统计）

- 合计 37 个文件 11,135 行；
- `core/launch` 4 个文件 1,337 行（MMMLC 本体 1,048 行，无 UI、无网络）；
- `launcher` 32 个文件 9,678 行，其中 `dlg/settings2.aardio` 3,409 行、8 个设置页；
- 与启动无关但有分量的模块：`m3mod` 598、`m3toml` 424、`m3zip`、`m3crash` 423、
  日志窗口筛选/打包。

**结论**

- 「专一」成立：所有增长都在"让任何整合包能正确地起来"这条线上，
  三件套的边界没破（core 不下载、launcher 不嵌游戏逻辑、下载器尚未开工）。
- 「简单」已从"整个程序"退化为"默认路径"：主页仍是下拉 + 两个按钮 + 状态栏，
  但设置抽屉有 8 页、版本覆盖 7 个键、另有一个 Mod 子页。
- 复杂度里有一部分是**换可靠性**（兼容各种不规范 JSON，方向正确），
  另一部分是**换功能**（Mod 管理、日志筛选），后者若继续长就会偏离 slogan。

**建议的判据**（待用户确认后再写进设计文档，不擅自改）

1. 新功能先过三问：让"启动"更可靠吗？不做会不会导致启动失败？能否放进独立工具？
2. 给"简单"量化：主页交互元素 ≤ 3；设置页数上限；版本覆盖键上限。
3. Mod 管理不再长大（不做批量安装 / 搜索 / 更新检查），未来可并入下载器或独立工具。
4. 正版与外置登录只占「账户管理」一页，不扩散成皮肤 / 好友 / 服务器列表。

## 追问：还算 minimalist 吗（21:10）

**结论**：按"交互与运行"算，按"功能面与代码量"不算；两者都要认，不能只挑有利的那个。

**通过的六条（可测）**

1. 首屏决策数 2（选版本、点启动），0 个必填设置；
2. 打扰 0：无广告、无推送、无强制登录、无自动更新弹窗、无遥测；
3. 单 exe、无运行时依赖、portable（删目录即卸载）；
4. 不看文档能启动；
5. 可预测：同样输入同样结果，不因更新改变行为；
6. 状态全在目录里（`config.json` + `versions`），无注册表、无隐藏状态。

**不通过的三条**

1. 11,135 行，其中与"启动"无直接关系的约 1,500–2,000 行（mod / toml / zip / 崩溃规则）；
2. 设置 8 页、`settings2.aardio` 3,409 行；
3. **真实使用中设置页是常态路径**：昨天五个实例的排查，每次都要开「Java 管理」「路径与版本管理」「版本独立设置」。
   这条最要紧——它推翻了"深度藏在设置里所以无害"的辩护。

**判断**

minimalism 不是存量而是**流量**：等于"拒绝了多少"，不是"现在有多少"。
昨天接受得多（日志筛选、Mod 页长大）、拒绝得少，拒绝率在下降。

**待用户决定**（不擅自改设计文档）

- slogan 精确化：`专一且克制`，或给 minimalism 三条可测注解；
- 「一进一出」配额：每加一页 / 一个覆盖键 / 一个按钮，必须删或合并一处；
- 把 v2 第 177 行已有的「外置成独立小工具」思路升级为通用规则。

## 追问二：好用与最初设想（21:25）

**用户观点**：它依然好用；但确实在偏离最初设想，而最初的设想来自"对启动器制作不了解"。

**判断**

1. 「好用」成立，而且是修出来的，不是堆出来的：昨天五个实例全部启动成功，
   代价是五条兼容规则（去重保位、分类器进 key、有 LWJGL3 去 LWJGL2、
   缺 downloads 按坐标补、Java 24+ 放行 Unsafe）——**合计约 120 行**。
   现象极复杂、代码极轻，这正是 minimalism 的正确形态：把复杂度**压缩成规则**，
   而不是**摊开成界面**。
2. 最初的设想是个**假设**："启动很简单，所以启动器可以很小"。
   昨天的工作证伪了前半句：启动本身不简单（JSON 不规范、加载器混装、类加载顺序、JVM 代际）。
   但**后半句仍然有效**：不简单的事实应该被启动器吸收，而不是转嫁给用户。
3. 所以漂移的不是"目标"，是"复杂度的落点"：兼容知识落进 core（对）；
   Mod 管理落进启动器（可商量）；日志筛选落进界面（可接受但不增加可靠性）。
4. v2 第 15 行自己写了退路：「精简不等于简陋：不以牺牲可定制性与美观为代价」。
   现在的状态是这句话的后半句赢了前半句——不是背叛文档，是文档内部的张力兑现了。

**建议的落点规则**（待用户定）

- 复杂度预算：`core/` 不设上限（换可靠性）；主页/通知/首屏 零增长；设置页 一进一出。
- 「Minimalism」只用来约束**界面与干扰**，不再用来声称**功能范围**。
