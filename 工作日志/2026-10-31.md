## 一、凌晨：0.1.0 发布踩的三个坑（摘要，详见 2026-10-30.md）

1. **滑块形状乱跳**：默认是圆、悬停变方块、移开不恢复。

   （`docs/specs/aproj.md:146`）。正确做法是右键工程目录 → **「同步本地目录...」**（同文件 `:152`）。

另外加了防护：`open_log_window` / `notice` 用 `try{...}catch(e){...}` 包住，
缺窗体时不再「什么都不发生」——前者照常启动游戏，后者退化到状态栏提示。

## 三、图标设计（10:40–11:00）

### 字体问题

用户想找「圆润的无衬线字体」，答案是 **Varela Round**（最常被想起的），同类还有
Nunito / Quicksand / Comfortaa / Baloo / Fredoka / M PLUS Rounded 1c，商业的有 Arial Rounded MT Bold、
SF Pro Rounded，中文对应体是**幼圆**。本机都没装，也没有网络下载，所以走几何绘制。

### 先做了一版几何圆头（备用）

M 和 ³ 都用「圆头笔画」画（沿路径撒点 + 端点圆），笔画粗细和圆度完全一致，任意尺寸重绘不失真。
³ 是「上碗 → 腰 → 下碗」一笔画。这版留在 `图标设计\` 目录里，没采用。

### 用户自己的设计（采用）

- `v1.png` / `v1.svg`：白底、细笔画 M + ³。
  实测：左右边距 60/59、上下 66/65（**居中很准**），墨迹 54%×49%，笔画 5.1%。
- `v2 round.png` / `v2 round.svg`：`<rect rx="64">` —— **白色圆盘**，四角 alpha=0。
  白底上看不出区别，深色背景才显形；这是圆形设计的真正价值（白底徽章）。

### 最终规格

| 项 | 值 |
|---|---|
| 圆盘直径 | 画布的 **94%**（留 3% 边距） |
| 大尺寸字迹（M³）宽度 | 圆盘直径的 **62%** |
| 32 / 24 / 16 | **去掉 ³**，只留 M，M 高 = 圆盘直径的 60% / 60% / 66% |

小尺寸去 ³ 是用户定的：16px 下 ³ 只会糊成一个灰点。

### 坑

Pillow 的 `save(sizes=[...])` 是**从同一张图重采样**，逐档独立渲染的图会被忽略
（第一次导出的 ICO 里 32px 还带着 ³）。改成手写 ICO 目录、每个条目塞各自的 PNG 才对：

```python
struct.pack("<HHH", 0, 1, len(sizes))               # ICONDIR
struct.pack("<BBBBHHII", w, w, 0, 0, 1, 32, ...)    # ICONDIRENTRY
```

### 产出

- `launcher\ICON design\MMMLauncher.ico`（7 档：256/128/64/48/32/24/16，32bpp，PNG 压缩）
- `icon-spec.md`（几何参数 + 在 SVG 里改哪些数值）
- `build_ico_raw.py`（生成脚本，改 `DISC` / `G62` 就能重出）

## 四、m3theme 用户库（11:00）

新增 `lib/m3theme.aardio`：把散落在各窗口的黑白灰和 skin 代码收成一处。

- **颜色**：`INK / WHITE / BG / MUTED / LINE / TRACK / DIS / DISFG / RED`（ARGB，给 plus 的 skin 用）
  外加 `C_INK / C_MUTED`（COLORREF，给 static / edit 的 `color` 属性用）——两套格式的坑写在注释里。
- **转换**：`toRef(argb)`，ARGB → COLORREF（灰色不用转，彩色才需要）。
- **皮肤**：`button` / `ghost` / `plain` / `rule` / `slider`。
- **文字**：`field` / `note` / `error`。
- 带 `intellisense(m3theme)` 块，IDE 里能补全。

**第一次运行就炸了（重要教训）**

报错：

```
lib\m3theme.aardio 行 11：不支持此操作: _set table
定义类型:self(namespace) 名字:'m3theme' 类型:null
```

原因：我在 `namespace m3theme { }` **内部**又写了 `m3theme.INK = ...`。
aardio 的 `namespace` 块里，默认命名空间就是这个命名空间本身——裸名字才是成员
（文档原话：`string = ..string  // self.string = global.string`），
所以 `m3theme.INK` 被解析成「当前命名空间里名叫 m3theme 的成员」（null），
再对它赋值就报 `_set table`。

**规则**：

- 命名空间内部写**裸名字**：`INK = 0xFF1A1A1A;`、`function button(ctrl){ ... WHITE ... }`
- 内部要访问**全局**对象（`print`、`math`、`string` 等）必须加 `..` 前缀：`..math.floor(...)`
- `type / tostring / tonumber` 这类内置保留函数不用加

**第二次运行又炸**：`Can't modify the constant: 'error'`。
我把错误文字接口命名成 `error`，而 `error` 是 aardio 的内置保留函数（和 `type`、`tostring` 同级），
在命名空间里用裸名字赋值会被当成"修改常量"。改名为 `danger` 后正常。

**命名空间成员命名黑名单**（踩过的）：`error / assert / type / tostring / tonumber / print /
loadcode / eval / call / invoke / select / pcall / unpack / next / rawget / rawset /
setmetatable / getmetatable / sleep / execute`。

改成裸名字后，`confirm.aardio` 正常。

**第一个使用者**：`dlg/confirm.aardio` 已经从 10 行 skin 代码变成两行
（`m3theme.button(winform.btnOk)` / `m3theme.button(winform.btnCancel)`），行为不变。

**顺带修了自己的检查脚本**：之前它把 `/**intellisense ... **/` 当成普通块注释，
但 intellisense 里还有 `__/*参数*/` 这种内联注释，普通的 `*/` 会提前闭合，
于是误报"括号不平衡"。改成把 `/**intellisense` 到 `**/` 整体跳过之后，
m3theme 和标准库 `fsys` 一样平衡——**说明这个误报是脚本的问题，不是代码的问题**。

**还没迁移任何窗口**——下一步按「小窗口先试」的顺序来：confirm → notice → about → 三个管理窗口 → settings → main。

## Tooltip 吃掉第一下点击（11:35）

**做了什么**

- `launcher/MMMLauncher/main.aardio`：状态栏的悬停提示从 `winex.tooltip.popup`（配合 200ms 轮询）
  换成 `win.ui.tooltip`（标准提示控件）。删掉 `check_status_tip()`、`status_tip_on`、轮询定时器。
- 新增 `refresh_tooltip()`：版本名变化时更新提示文本，`refresh_status()` 末尾调用。

**为什么**

- 现象：tooltip 出现后，必须先点一下窗口才能继续操作。

**踩坑**

- 根因在 `lib/winex/tooltip.aardio:60`：`trackPopupEx` 里执行了 `this.capture = true`，
  提示框抢走**鼠标捕获**（这是它"点外面关闭"的实现方式），
  于是提示显示期间的第一次点击被它消费掉，第二下才落到窗口上——正是用户描述的现象。
- 换成 `win.ui.tooltip(winform)`：该构造器默认 `defaultFlags = 0x10 /*_TTF_SUBCLASS*/`
  （`lib/win/ui/tooltip.aardio:20`），是系统标准悬停提示，自动显示/隐藏、不 capture。
- **别用 `win.ui.tooltip.tracking()`**：那个构造器会把默认 flags 设成 `TTF_TRACK`（手动模式），
  必须自己调 trackPopup，又会绕回捕获问题。

**待办**

- 用户验证：鼠标停在状态栏 → 提示弹出 → 这时直接点「设置」应该一次就响应。
- 提示改成系统标准后会有约 0.5 秒悬停延迟（原来是自己轮询的立即弹出），如果觉得慢，
  那是系统 `TTM_SETDELAYTIME` 的默认值，可以再用 `status_tip.setDelayTime()` 调（先看用户反馈）。

**补充：换完之后 tooltip 完全不出现了（11:40）**

- 原因：`static` 控件默认**没有 `SS_NOTIFY`**，`WM_NCHITTEST` 返回 `HTTRANSPARENT`，
  鼠标消息穿透到父窗口，控件自己收不到 `WM_MOUSEMOVE`。
- 而 `TTF_SUBCLASS` 的 tooltip 是靠**子类化工具窗口本身**来检测悬停的——控件不接收鼠标消息就永远不触发。
- 修法：`main.aardio:44` 把 `SS_NOTIFY` 和 `SS_ENDELLIPSIS` 一起 `modifyStyle`：

```aardio
win.modifyStyle(winform.lblStatus.hwnd, 0, 0x4000/*_SS_ENDELLIPSIS*/ | 0x100/*_SS_NOTIFY*/);
```

- 备选方案（如果还不行）：把 `lblStatus` 换成 `plus` 控件，plus 自己处理鼠标消息，挂 tooltip 更可靠。

## 静态文本背景 / 错误色偏黑（11:55）

**做了什么**

- `lib/m3theme.aardio`：
  - 新增 `C_BG = 0xF2F2F2`、`C_RED = 0x3030D0`，新增 `ink(ctrl)`。
  - `note` / `ink` / `danger` 现在同时设置 `color` 和 `bgcolor`；`field` 只设 `color`（输入框要保留白底）。
  - `toRef` 改成纯除法取字节，并修正 R/B 通道。
- `dlg/theme_test.aardio`：标题、主文字、滑条数值改用 `m3theme.ink()`。
- `main.aardio`：`lblStatus.bgcolor = 0xF2F2F2`。

**为什么**

- 现象 1：窗口里的文字背景和空白背景有细微色差，看起来像"用背景区分主次文字"。
- 现象 2：测试台的「错误文字」显示成黑色。

**踩坑**

- **静态文本的背景**：aardio 的 `static` 默认用 `COLOR_BTNFACE`（0xF0F0F0）画自己的背景，
  而窗口 `bgcolor` 是 0xF2F2F2，差 2 个色阶 → 每段文字背后露出一块浅灰。
  解法是显式 `ctrl.bgcolor = C_BG`，不是"用背景区分文字"——这是它默认值跟窗口不一致。
- **`toRef` 把大数位移搞坏了**：`0xFFD03030` ≈ 4.29e9，超过 2^31，
  `argb >> 16` 按 32 位有符号解释时结果不可靠，取到的通道值变成 0 → 颜色算出来是黑的。
  改成 `math.floor(argb / 0x10000) % 0x100` 这类纯算术，避开位移。
- 顺带修正通道方向：**ARGB 低字节是 BB，COLORREF 低字节是 RR**，R 和 B 必须互换
  （我第一版改的时候换错了，又验了一次才对）。

**待办**

- 用户验证测试台。
- 其它窗口迁移到 `m3theme` 时，静态文本要用 `ink / note / danger`（它们会顺手设 `bgcolor`），
  不要只设 `color`，否则还会出现浅灰底。
