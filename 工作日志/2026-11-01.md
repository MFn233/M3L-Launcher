## 关于界面文案风格的讨论（21:45）

**结论**

- 用户指出：我的界面提示和代码注释偏口语，和常见的专业软件不一致。
- 原因分析：我的默认写法接近英文 SaaS / indie 产品的 plain language
  （第二人称、解释因果、安抚语气），直译成中文就是啰嗦 + 翻译腔；
  中文软件的惯例是**书面、克制、名词化、短句**。
- 两种传统都真实存在：Apple HIG、plain language 运动、GitHub、微信都偏口语但**极短**；
  银行 / 政务 / 旧 Win32 企业软件偏正式书面语。我学的是前者，但学过头了（不够短）。
- 本项目采用后者的写法：陈述句，短句，不写"你/我们"，不解释因果（原因进日志），
  错误信息三段式（现象 / 原因 / 处理），注释只写"为什么"。

**待办**

- 等用户确认后，按这套规范回改现有文案（界面 + 注释）。

## 加载器误判出「Forge 7.0.1 + Forge 47.4.22」（22:10）

**做了什么**

- `lib/m3version.aardio`：
  - 加载器识别从「group 关键字匹配」改成 **artifact 精确匹配**（新表 `EXACT`）；
  - 同一个加载器只记一次（`seen[loader]`），不再出现重复标签；
  - 整条链上一个本体都没找到时，才用 group 关键字兜底（新表 `FALLBACK`，**不带版本号**），
    最后才用 `mainClass` 猜。

**为什么**

- 用户截图里出现 `Forge 7.0.1 + Forge 47.4.22` 这种组合，明显不对。
- 原因：Forge 的版本 JSON 里除了本体 `net.minecraftforge:forge:1.20.1-47.4.22`，
  还带一堆同 group 的辅助库：`net.minecraftforge:forgespi:7.0.1`、`coremods:5.2.4`、`unsafe:0.9.2`。
  按 group 关键字匹配时，这些也被当成「又一个 Forge」，版本号还取了 SPI 的 `7.0.1`。

**踩坑**

- Maven 坐标里 **group 只说明归属，artifact 才说明是什么**。按 group 匹配必然把辅助库误认成加载器。
- 顺带确认版本号含义：Forge `47.4.22` / `47.3.0` / `47.3.27` 都是给 MC **1.20.1** 的 Forge 小版本，
  这三条原本是三个不同的实例，不是识别错乱。

**待办**

- 用户重开「设置 → 版本管理」，确认每行的加载器只剩一个标签（如 `Forge 47.4.22`）。

- `lib/m3version.aardio`
  - 用 `found` 布尔标记取代「`out.game == name`」这种哨兵；
  - 新增 `version_token()`：`26.1-snapshot-4`、`26.2-pre-4`、`1.20.1-rc1`、`b1.7.3` 整段原样使用；
  - 判断顺序改为：`clientVersion` → **`m3l_game`** → `inheritsFrom` → `id` → 文件夹名
    （最后还会在名字中间找一次版本号，覆盖 `LabyMod-4-1.12.2-xxx` 这种命名）。
- `dlg/versions.aardio`：重命名前先 `m3version.describe()` 算出真实游戏版本，写进 JSON 的 `m3l_game`，
  再照旧把 `id` 改成新名字。

**为什么**

- 用户提出：把 1.7.10 改名成 1.8.10，会不会显示成 1.8.10？——**会**。
- 原版 JSON 没有 `clientVersion`，只能靠 `id` 认版本；而重命名**必须**改 `id`：
  core 用 `info.id` 填 `${version_name}`（即 `--version` 参数），不改的话游戏会去找
  `versions/<旧名>/<旧名>.json`，直接启动失败。所以只能"改 id 的同时把真相存一份"。

**踩坑**

- 用「`out.game == name`」当"还没找到"的哨兵是错的：**原版版本的 `id` 恰好等于文件夹名**，
  于是认出来的版本又被最后一句 `if (out.game == name) out.game = "未知"` 覆盖成未知。
  这就是之前 `1.11.2` / `24w33a` / `b1.7.3` 全显示「未知」的真凶，和 clientVersion 缺失是两个问题。
- 教训：状态要用独立布尔标记，不要拿"结果值是否等于某个输入"当哨兵。

**待办**

- 用户验证：拿一个 1.7.10 改名成 1.8.10，游戏版本列应仍显示 `1.7.10`。
- 本轮之前重命名过的版本没有 `m3l_game`，仍会显示改名后的名字（信息已丢，无法恢复）。

## 回退 m3l_game，研读 HMCL 源码（22:20）

**做了什么**

- **回退**：
  - `dlg/versions.aardio`：重命名时不再往 JSON 写 `m3l_game`，恢复成只改 `id` / `jar`；
  - `lib/m3version.aardio`：删掉 `m3l_game` 的判断分支，顺序回到
    `clientVersion` → `inheritsFrom` → `id` → 文件夹名。
- `dlg/versions.aardio`：重命名补上**失败回滚**——json 或 jar 改名失败时把目录改回原名，
  不留下「目录叫新名、json 还是旧名」的半成品状态。

**为什么**

- 用户认为往 Mojang 的版本 JSON 里塞自定义字段不是好做法，要求回退并参考 HMCL 的实现。

**调研（HMCL v3.2.115，源码经 gitee 镜像获取）**

- `DefaultGameRepository.refreshVersionsImpl()`
  - 版本**目录名就是 id**；
  - `<目录>/<id>.json` 不存在、但目录里只有一个 json 时，自动把它改名成 `<id>.json`（自愈）；
  - JSON 里的 `id` 与目录名不一致时，**直接改写 JSON**（`setId(id)` 后写回）。
- `DefaultGameRepository.renameVersion(from, to)`
  - 改目录名 → 改 `<from>.json` / `<from>.jar` 文件名；
  - 任一步失败就**整体回滚**（recovery 分支）；
  - `jar == id` 时 `setJar(to)`，最后 `setId(to)` 写回 JSON。
- `Version.java` 里**没有 gameVersion 字段**，`id` 就是唯一身份；`getVersionJar` 用 `jar ?? id`。
- 结论：**HMCL 同样不保留"原始游戏版本"**，改名后也只能靠名字解析——和我们回退后的做法一致。

**待办**

- 等用户选择：① 与 HMCL 保持一致（现状）；② 在版本目录放边车文件（如 `.m3l.json`）记录真实游戏版本，
  既不动 Mojang JSON，也能跟着目录走。

- `lib/m3crash.aardio`、`lib/m3pack.aardio`：同样把遍历 `fsys.list` 结果的通用 `for i, name in files`

## DPI 适配：列宽换算 + 读数（00:35）

**做了什么**

- `lib/m3list.aardio`：`fit()` 里先用 `ctrl.dpiScaleX` 把 `getRect()` 的设备像素换算成逻辑像素，
  再和列宽比较。之前直接拿设备像素比逻辑列宽，**150% 缩放下会误判"放得下"**。
- `dlg/theme_test.aardio`：底部新增 DPI 读数行
  `DPI 1.50×　列表 852 设备px → 568 逻辑px`，测 DPI 时对着这行看。

**为什么**

- 用户要做最后一轮 DPI 测试。先修掉已知的换算错误，否则 150% 下必然出现
  「列被挤出屏幕」的老问题，会把测试结论带偏。

**踩坑**

- aardio 有**两套坐标**：`win.form` / `winform.add` 的构造参数是逻辑像素（会被 DPI 缩放），
  而运行时的 `getRect()` 等是设备像素。两者混用是高 DPI 下的经典坑。

**待办**

- 用户按 100% / 150% 各跑一遍，看是否有文字截断、控件错位、列宽溢出。

## F5 时关于窗口显示成 aardio 的版本（00:50）

**做了什么**

- `dlg/about.aardio`：读 exe 版本前先校验 `productName == "M^3 Launcher"`，
  不是我们的 exe 就不覆盖窗体里写好的版本文字。

**为什么**

- 用户反馈：F5 直接运行时，关于窗口显示的是**aardio 工具套件的版本号**，以为出错了。
- 根因：F5 调试跑的是 aardio 的宿主 exe，它自带的版本资源是工具自己的；
  `io._exepath` 指向那个 exe，于是读到的是它的版本。
- 用产品名判断最干净：工程属性里 `ProductName="M^3 Launcher"`，宿主 exe 不是这个值。

**踩坑**

- 「读 exe 版本」这类做法要先确认**读的是哪个 exe**——调试宿主和发布产物往往不是同一个文件。

**待办**

- 版本号以后改两处：工程属性 `x.x.x.x`（第四段自动增）+ `about.aardio` 里 `lblVer` 的初始文字（前三位）。
  发布版会自动读工程属性，F5 时用初始文字兜底。
