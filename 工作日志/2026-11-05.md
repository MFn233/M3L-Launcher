## 鸣谢页面 + 多实例崩溃窗口（21:30）

**做了什么**

- 新增 `dlg/credits.aardio`（520×356）：三行鸣谢——
  `aardio / 开发工具与运行时`、`Mojang / Minecraft 本体与版本清单格式`、
  `HMCL / 崩溃原因分析规则的参考实现（GPL-3.0）`，下方两行小字说明非隶属关系与商标归属。
- `dlg/about.aardio`：加「鸣谢」按钮（ghost 样式，在「确定」左边），点开上面的窗口。
- `dlg/crash.aardio`：关闭按钮和 Esc 从 `endModal(true)` 改成 `close()`——
  多开时崩溃窗口是**非模态**的，`endModal` 对它无效；模态调用（测试台）时 `close()` 一样会让 `doModal` 返回。
- `main.aardio`：
  - `open_crash_window()` 末尾从 `frm.doModal(winform)` 改成
    `win.setOwner(...)` + `frm.center(winform)` + 错位 + `frm.show()`；
  - 新增全局 `crash_seq`，第 2 个以后的崩溃窗口按 `28px` 阶梯错开，避免完全叠在一起看不出是多个；
  - `finish_instance()` 不再被崩溃窗口阻塞，能继续处理下一个退出的实例。
- `dlg/crash_test.aardio`：抽出 `build_crash_form(sample, idx)`；新增「连开 3 个」按钮，
  一次开出三个非模态崩溃窗口用来验证多实例。

**为什么**

- 用户要求：关于里加鸣谢；实现多实例崩溃窗口并给测试方法。
- 原来的实现是模态的，第二个实例崩溃时会被第一个窗口挡住，看起来像"没反应"。

**踩坑**

- 非模态窗口必须用 `close()` 收尾，`endModal()` 只对 `doModal` 打开的窗体有意义。
- 非模态窗口如果不设 owner，主窗口关掉后它们会留着；`win.setOwner(hwnd, owner)` 让它们跟着主窗口一起关。

**测试方法（已备好）**

1. **不崩游戏**：调试模式 → Ctrl+右键标题 → 崩溃测试台 → 「连开 3 个」，应同时出现三个窗口，
   且互相错开 28px。
2. **真崩**：工作区里已放好一个假版本 `test\.minecraft\versions\_crash-test`
   （`mainClass` 指向不存在的类，启动必挂）。在设置里切换到它，连点两次「启动游戏」，
   应出现两个崩溃窗口，且第一个不关也能看到第二个。

## 许可证兼容性：MIT 与 GPLv3 是单向兼容（21:55）

**结论**

- **MIT → GPLv3：兼容**。MIT 代码可以进 GPLv3 项目，整体按 GPLv3 分发。
- **GPLv3 → MIT：不兼容**。不能把 GPLv3 代码改许可证成 MIT，衍生作品只能继续 GPL。
- 换句话说：兼容性是**单向**的，方向决定了义务，不是"互相兼容"。

**对本项目的意义**

- 现状：`about.aardio` 和 `设计文稿/design.md` 都写着 MIT，但工程里**没有 LICENSE 文件**。
- 崩溃原因分析那套规则（`lib/m3crash.aardio` 的 23 条）是照着 HMCL 的
  `CrashReportAnalyzer.java`（GPL-3.0-or-later WITH AdditionRef-HMCL）翻写成 Lua 模式的。
  从版权角度，规则清单的**选择与编排**属于受保护的表达，直接改写通常算衍生作品。
- 因此在源码里既写 MIT、又在鸣谢里承认"参考 GPL-3.0 实现"，是**自相矛盾**的：
  鸣谢不构成 GPL 合规，GPL 要求的是许可证、源码与声明。

**两条出路（待用户选择）**

1. **改成 GPL-3.0-or-later**：一处声明 + 加 LICENSE 文件即可；诚实、省事，但与"独立项目、随便拿去用"的初衷有冲突。
2. **重写规则表**：不照 HMCL 的清单，改为从真实崩溃报告和公开发布的游戏日志格式里自行归纳，
   写完删掉鸣谢里的 HMCL 行——这样 MIT 才站得住。工作量大一些，但是"干净"的那条路。

**待办**

- 等用户决定走哪条；在此之前不动许可证声明。
