## Mod 扫描统计崩在递减循环上（17:10）

**现象**（用户截图）

```
文件:...MMMLauncher\dlg\settings2.aardio
错误行号:#1289
不支持此操作: _get table
定义类型:variable(local)
名字:'r'  类型:null
```

**根因**：aardio 的 `for` 是 `for(起, 止, 步)`，中间是**止值**，不是条件：

```aardio
// 错：把布尔当止值，i 会越过 #keys
for i = #keys; i >= 1; 1 { ... var r = keyed[keys[i]]; r.ms ... }

// 对：
for i = #keys; 1; -1 { ... }
```

i 越界后 `keys[i]` 为 null → `keyed[null]` 为 null → `r.ms` 报 `_get table 名字:'r' 类型:null`。

**为什么以前没炸**：这段是"取最慢 5 个 mod"的统计，只有某次元数据读取
≥30ms（冷缓存）才会有 `slow` 条目；之前一直没触发到。

**改法**：递减改成 `for i = #keys; 1; -1`，并加 `if (!r) break;` 兜底。
顺手全项目扫了一遍同类写法（`for …; 条件; …`），没有第二处。

**沉淀**

- 递减遍历一律写 `for i = #t; 1; -1`；以条件控制循环用 `while`。
- 这类错误静态检查抓不到（括号是平的），只能靠"跑一次那条路径"或代码评审。

## 微软登录：浏览器已成功，启动器却报错（18:35）

**现象**（用户截图）：浏览器显示「你现在已登录到 M3L Launcher」，弹窗却显示
`[失败] 服务器没有返回内容`。

**根因**：`inet.http` 在**非 2xx** 时返回三个值：

```aardio
return false, html, status;   // ok=false, 响应体, 状态码
```

我只写了 `resp = http.post(...)`，拿到的是第一个值 `false` → 判成"没有内容"。
而微软在等待授权时返回的正是 **HTTP 400 + `{"error":"authorization_pending"}`**，
于是第一次轮询就把登录判死。

**改法**：`json_call` / `form_call` 都改成 `var ok, resp, status = http.post(...)`，
并把错误信息带上状态码与响应片段：

```
请求失败（HTTP 400）
返回内容不是 JSON（HTTP 500）：<前 120 字>
```

**教训**：**多返回值必须按个数接**。这已经是第三次踩同类问题
（`dedupe_by_key` 只接一个返回值导致剔除失效；今天这个只接一个导致登录判死）。
以后凡是调用可能返回多值的函数，先查文档或库源码确认返回值数量。

## inet.http 的返回值有两种形状（18:45）

修完上一处后，设备码这一步又报"设备码申请失败"。看了库源码才明白：

```aardio
// 成功：只返回响应体（一个字符串）
return ret;                    // ret = this.readAll()

// 非 2xx：(false, 响应体, 状态码)
return false, html, status;
```

所以 `var ok, resp, status = http.post(...)` 在**成功**时得到的是
`ok = 响应体, resp = nil, status = nil` —— 我的代码见 `resp` 为空就返回空表，
`device_start` 拿不到 `device_code`，于是报"设备码申请失败"。

**改法**：加 `split_result(http, r1, r2, r3)` 统一处理

```aardio
if (type(r1) == "string") { resp = r1; ok = true; }   // 成功
else { resp = r2; }                                   // 失败时响应体在第二个
return resp, (http.statusCode or r3 or 0), ok;
```

**教训**：同一个函数**返回值个数不固定**（成功 1 个、失败 3 个），
比"固定 3 个"更阴——按 3 个接会把成功当成失败，按 1 个接会把失败当成"没内容"。
`inet.http` 的 `post/get/request` 全族都是这个形状，以后一律走 `split_result`。

## 外置登录了却显示"离线"（18:40）

**三处显示 bug**

1. `main.refresh_status`：状态栏开头写死 `"离线登录"`，完全不看账号类型 —— 这就是用户看到的"离线"；

- 状态栏按 `acc.type` 给：`msa → 正版登录`、`authlib → 外置登录`、其余离线；

- 顺手把**日志落盘路径提前**到账号处理之前：账号、Java、兼容处理这些提示都在读 JSON 之前产生，
  原来晚设导致它们进不了 `m3l-launch.txt`（外置登录的提示就是这么丢的）。

**教训**

- 所有"按账号类型分支"的地方要一次性找全：状态栏、列表、摘要、启动参数，
  少一处就会出现"明明登录了却显示离线"这种迷惑现象。
- 用户报"登录没生效"时，先看启动命令里的 `--accessToken`/`--uuid`/`-javaagent`，

## 账号身份改为 type:name + 状态栏修复补回（22:20）

**用户反馈两条**

1. 不允许禁止同名不同属性的账号（离线 / 正版 / 外置各一个同名）—— 这是需求，不是 bug；
2. 主页状态栏仍显示"离线登录"。

**先查第 2 条**：代码里 `refresh_status` 还是 `var head = "离线登录";`
—— 说明**上一轮的修复没落盘**。

**根因（我自己的工具 bug）**：patch 脚本对同一个文件的**多条改动**都基于同一份
原始内容生成，最后逐条写盘时**后写的覆盖先写的**。上一轮 main 有两条改动
（状态栏、落盘提前），结果只有后一条留下。已改成"每文件按顺序应用，最后写一次"。

**第 1 条：身份键改造**

原来的身份是**名字**，所以同名必然撞车（`find_account` 只能返回其中一个）。
改为 `type:name`：

- `m3config.key_of(a)`、`find_by_key(cfg, key)`、`current_account(cfg)`；
- 配置新增 `account_key`；`current_account` 优先按键找，旧配置没有键时退回按名字
  （并优先带凭据的那个，保证老配置也能显示对）；
- 账户页：列表 `[当前]` 标记、选中项恢复、`acc_index()`、"设为当前"、登录落库
  （先按 UUID、再按 `type:name`）全部改用键；
- 重名限制放宽：只拦**同类型**同名（离线/正版/外置可以各有一个同名）；
- `user_summary` 改用 `current_account`。

**顺带修的时序 bug**

删除账号时，"当前账号是否被删"的判断在数组重建**之后**才取 `cfg.accounts[i].type`，
此时下标已经指向别的账号甚至越界。改为删除前先记下 `del_key`。

**教训**

- 写 patch 脚本时，**同一文件的多条改动必须在同一个内存副本上依次应用**，
  不能各自基于原文生成后一起写。
- 身份/唯一性问题：只要用户能"同名不同属性"，就必须有**复合键**，
  靠名字兜底只会制造"登录了却按离线"这种迷惑现象。
